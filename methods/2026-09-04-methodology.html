通用型方法论手册

换项目、换业务线都能直接套用的组织能力杠杆资产：技能研发流水线、知识库与数据中台、交付物规范、自动化集成、多 Agent 协同。

通用型方法论手册（v1.0.0）

本文从《[AI 平台] 对话价值汇总》拆出「通用型」部分，独立成册。内容不依赖具体业务，换个项目、换条产品线都能直接套用——是组织能力的杠杆资产。
已入库 [本地 RAG] business-alex，供所有接入的 Agent 检索调用。

0. 怎么用这本手册

  • 遇到"要做个新技能 / 新方案 / 新看板"类任务，先翻对应小节，照流程走，别从零造轮子。
  • 凡标注"强制"的，是用户长期踩坑后定的硬规矩，优先遵守。

---

1. 技能（Skill）研发与交付流水线

  • 分层开发 + 独立审计 + 版本化打包 + 按阶段回滚：每个技能分层实现，每层独立审计、打语义化版本号、可单独回滚，避免一次性大包难以排查。
  • 审计优先、先修缺陷再升级（最高优先级，强制）：收到别人的代码 / AI 产出 / 工程包，默认先读懂并审计（完整性、质量、真实可用性、风险），给 P0/P1/P2 分级意见，先把缺陷修好，再谈功能升级。绝不一上来就 build 或加链路。例外：用户明确说"直接做 / 帮我实现 / 接上 XX"才进 build 模式。
  • 通用母版 → 业务分支（强制）：新技能先做通用型跑通验证，再单独存为业务分支（如 ad-plan-generator 通用版 + ad-plan-generator-[category]s [品类 A]分支并存）。母版只承载通用逻辑，行业特定约束只叠加在分支，互不回写。
  • 安全准入审计（skills-security-check）：对第三方 Agent Skill 走云鼎 P0/P1/P2 框架，全量验证（非抽样），审计结论对照源码，附 SHA-256 哈希。
  • 一键防呆安装：面向零基础同事（HR/行政），安装只需输入单个 [[回调地址] 地址] 等极简参数，管理端/员工端双版本同步迭代。

2. 本地知识库 / 数据中台搭建方法论

  • [本地 RAG] 本地 RAG 部署踩坑清单（已实测）：
  • 容器 restart=unless-stopped + 绑定 [host:port] → 开机自启、本机任意 Agent 随时可拉起。
  • v1.15.0 中 /workspace/{slug}/update 是"改设置"假入口，会回 "No valid fields to update!"；真正加文档的端点是 POST /api/v1/workspace/{slug}/update-embeddings，且 adds 传文档相对路径（如 custom-documents/.json），不是文档 id。
  • 多个看似存在的路由（/document/upload、/documents、/workspace/{slug}/documents）实为 SPA 假路由，返回 HTML 200 导致静默失败。
  • 系统上传响应里的 id 与持久化后的 localFiles.id 不同；attach 必须用 storage 里的 location，不能用上传响应里的 id。
  • 上传接口 POST /api/v1/document/upload（multipart，字段 file）的响应里直接给 location 字段，拿它去调 update-embeddings 即可。
  • [本地推理] 本地推理接入：[本地 RAG] 的 chatProvider 设 [本地推理]、chatModel 用 [本地 LLM]:7b，经 [docker host] 连通，免云 API 依赖、数据不出本机。
  • 零依赖 MCP Server 写法：纯 stdlib（urllib）+ JSON-RPC stdio，不依赖 requests；用 while True: readline() 而非 for line in stdin（管道会吞最后一行）。已落地 [本地 RAG]_mcp_server.py，暴露 query_knowledge_base 与 list_documents 两工具，[AI 平台] / [Agent 客户端] 共用。
  • 数据中台 6 层架构：采集 → 归一化 → 核算 → 分析 → 推送 → 交互；[国内 ERP] ERP（国内多平台）与[跨境 ERP] ERP（Amazon 财务）双源，Flask API + ECharts + SQLite 云部署（[数据中台]）。

3. 交付物规范（强制）

  • 语义化版本号 + 强制递增：所有可交付文件统一「中文内容名-v版本号」格式，初版 v1.0.0；每次更新（含一处修正）必须 bump 版本，绝不当覆盖。
  • Excel(xlsx) 优先：能结构化的内容（对照表、清单、拆解、打卡、考核、数据）默认出 xlsx；Word 只留给强叙述/方案正文/公文。
  • Word+PPT 双格式：正式方案默认 docx + pptx 双交付，PPT 含表格层级、英雄/过渡页、技术蓝渐变主题。
  • 前后对照 + 待确认标注：修订类交付必须含"调整前后对照表"和明确"待确认"标记，保证可核验、可复现。
  • 去 AI 味润色：所有叙述性正文默认走 humanizer-zh 规则（删填充词、破公式结构、变节奏、删宣传语/金句/三段式/冒号标题列表/破折号滥用），保留表格数据与术语准确性。

4. [IM] / 自动化集成

  • [IM]群机器人固定分配（单一事实源）：[[回调地址] 注册表] 技能的 [事实源文件] 是唯一事实源，绑定只认它；任何 [回调地址] 改动必须走 [变更脚本]（自动写更改前后日志）。现行主群 [主群/废弃群]，旧 [主群/废弃群]/[视觉生产]_group 已废弃。
  • 每日[IM]对话摘要看板：聚合全量会话、待办、@提及、OA、考勤、请假、日历，推送格式 Markdown 摘要 + 整页 PNG dashboard（[整页截图]，设备比例克制以适配[IM]显示高度）。
  • [IM]推图规范：看板大屏作图片推群（非 [卡片消息] 文字）；截图 [整页截图]；高度克制（图表≤220px、表格≤Top12、[截图缩放] 1.5、比例~1.1）避免[IM]只显示上半截。
  • [IM] [审批流程]自动化技能：管理端+员工端双版本，已沉淀为可打包部署的一键安装技能。

5. 多 Agent 协同范式

  • 本机 Agent（[AI 平台] / [Agent 客户端] / [LLM 引擎] Harness）通过本地 MCP Server 共享同一份 [本地 RAG] 知识库，避免各自为政、知识孤岛。
  • 通用型技能与业务分支并存，既保证跨 Agent 复用，又隔离行业敏感逻辑。
